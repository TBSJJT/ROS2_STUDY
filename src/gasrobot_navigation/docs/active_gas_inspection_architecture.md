# 气体主动巡检整体框架

## 1. 必须遵守的基本原则

气体采样与导航航点是两套不同机制：

- 航点只负责告诉 Nav2 机器人应当怎样覆盖场地；
- 气体采集节点按固定频率连续采样，并给每条数据写入 ROS 时间戳；
- 机器人运动、横移、转弯、临时停车时都不能停止采样；
- 气体读数的位置由数据时间戳对应的 TF 历史位姿确定，不能简单使用“当前巡检点”的坐标；
- dwell_sec 只是可选的静止观察时间，不是采样开关。

## 2. 当前已经实现的正常巡检

```text
路线 YAML
   ↓
inspection_manager
   ↓ 逐点发送 NavigateToPose
Nav2 全局规划器和局部控制器
   ↓
/cmd_vel
   ↓
gasrobot_base → STM32 底盘

gasrobot_gas（独立连续运行）
   ↓ /gas/readings
inspection_manager（仅用于任务反馈）
```

当前阶段实现：

1. 加载并严格校验命名路线；
2. 使用与 Nav2 相同的地图校验初始化位姿和全部航点；
3. 禁止航点进入障碍物、未知区域或距离边界过近；
4. 等待 Nav2 就绪后，一次只发送一个 NavigateToPose 目标；
5. 目标成功后立即发送下一点，默认不静止等待；
6. 支持超时、有限重试、暂停、继续、取消和任务结果；
7. 持续接收 /gas/readings，但不在导航层生成气体结论；
8. 严重 RiskEvent 可以按路线安全策略取消当前导航。

正常巡检的核心伪代码如下：

```text
开始任务(route)
等待 Nav2 就绪

对每一圈：
    对路线中的每一个航点：
        如果收到取消或安全停机：
            取消当前 Nav2 目标并结束

        向 Nav2 发送一个 NavigateToPose
        异步等待成功、失败或超时

        如果失败：
            按配置重试
            重试耗尽后停止任务或跳过该点

        如果成功且 dwell_sec > 0：
            执行可中断的静止观察

报告本轮任务结果
```

## 3. 连续气体采集节点的预留逻辑

gasrobot_gas 后续应按类似逻辑实现，不能由巡检点触发：

```text
以 10 Hz 定时执行：
    读取 MiCS-5524、酒精确认传感器、温度和湿度
    使用原始 ADC 值计算相对响应
    写入统一 ROS 时间戳
    发布 /gas/readings
    把原始数据写入 rosbag 或实验记录
```

气体采集节点不直接发布 /cmd_vel，也不直接修改 Nav2 控制器。

## 4. 后续主动气源搜索框架

当前版本只真正执行 PATROL，其余状态暂不写入运动控制代码：

```text
BASELINE
    在确认的清洁环境建立传感器基线
    ↓
PATROL
    按固定覆盖路线巡检，同时连续更新气体地图
    ↓ 弱异常持续出现
SUSPECT
    降低任务速度，继续采样并检查异常是否持续
    ↓ 证据充分
BACKTRACK
    结合最近一段历史轨迹和传感器动态响应估计候选区域
    ↓
LOCALIZE
    从候选采样点中选择下一个信息增益较高且可达的目标
    ↓
CONFIRM
    多方向复测候选区域并计算置信度
    ├── 成功：REPORT
    └── 证据不足：PATROL
    ↓
RESUME
    回到被中断的固定巡检路线
```

未来任务监督器只负责以下高层操作：

```text
读取气体地图和候选区域
选择下一个采样目标
取消或抢占当前 NavigateToPose
向 Nav2 发送新的地图目标
保存固定路线的未完成索引
局部搜索结束后恢复正常巡检
```

Nav2 仍负责避障、路径规划和速度控制，气体算法不得同时向 /cmd_vel 发布另一套速度，
避免两个控制源互相覆盖。

## 5. 数据关联

连续读数至少应保存：

- 传感器原始 ADC 和相对响应；
- 数据时间戳；
- 温度和湿度；
- map → gas_sensor_link 的历史 TF；
- 机器人线速度和角速度；
- 当前任务状态、当前目标航点和路线圈次。

离线实验时，应使用同一份 rosbag 分别计算当前位姿关联、固定延迟补偿、
历史位姿加权关联和 Kernel DM+V，保证算法对比使用完全相同的原始数据。
