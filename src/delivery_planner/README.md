# 车间配送代价与规划

本包提供独立的 Nav2 静态有向距离矩阵采集入口。当前实现为距离阶段：
物料站和六个工位共 7×7 项，每个非对角点对重复规划3次，共126次规划请求；对角线为零。
已实现独立时间标定工具、可编辑截止时间模型和最多 8 工位的精确枚举。
NSGA-II 尚未实现；完整时间矩阵必须通过实际采样才能使用，不能把工具存在视为标定完成。

## 构建与运行

```bash
cd /home/iceice/ROS_Project/study/ros_ws
source /opt/ros/humble/setup.bash
colcon build --symlink-install --packages-up-to delivery_planner
source install/setup.bash
ros2 launch delivery_planner cost_matrix.launch.py
```

不需要启动 Gazebo、AMCL 或配送管理器，不会发送导航目标或速度指令。
本入口在 `/cost_matrix` 命名空间启动地图服务器、Nav2 规划器及生命周期管理器，
每个规划目标使用 `ComputePathToPose.use_start=true` 明确提供起点和终点。
专用 TF 位于 `/cost_matrix/tf[_static]`，仅为静态栅格提供原点，不是车辆定位。
全部工具使用系统时间，因此也不需要 `/clock`。采集结束自动关闭本入口节点。
请勿同时启动两套同名矩阵采集入口。

可选参数为 `output_dir`、`map`、`stations_file`、`params_file`、`planner_id`。
默认输出到工作空间 `runs/cost_matrix_时间_随机编号/`；指定的目录必须不存在。
地图和工位的哈希绑定校验与配送系统相同，自定义地图必须重新标定工位。

## 代价定义与来源

- 米制距离由 Nav2 原始路径中相邻二维点距离求和，不用起终点直线距离代替。
- 正反方向独立计算；不假设路径对称。失败项保留状态，距离为 `null`。
- 使用已保存地图静态层、现有 footprint、膨胀层和 Navfn 参数。
- 专用参数移除实时激光障碍层，关闭静态层 footprint 清除，避免采样期间环境变化。
  实际车辆导航的参数文件没有修改，仍启用实时障碍感知和局部控制。
- 每个点对前后检查代价栅格哈希，变化时停止并保留不完整结果，不能作为正式缓存。
- 这是**规划几何距离**，不是机器人实际轨迹长度，也不是实际行驶时间。
  `planning_wall_sec` 是规划器计算耗时，绝不能拿它作为行驶耗时。

## 输出与缓存

| 文件 | 内容 |
|---|---|
| `matrix.json` | 42 次请求的状态、原始路径点、距离、完整性和内容哈希 |
| `distance_m.csv` | 可读距离表；失败为 `unavailable` |
| `costmap.json` | 本次实际规划栅格及空间元数据 |
| `provenance.json` | 所有输入快照的 SHA-256 和派生参数 |
| `snapshots/` | 地图、工位、导航参数、模型 Xacro、控制器、场景及规范化规划配置 |
| `runtime_nav2.yaml` | 此次实际启动使用的派生参数 |

`complete=true` 表示所有点对都有结果，`all_reachable=true` 才表示全部成功。
工具失败会保留 `error` 和已完成点对；不要只看 launch 退出码判断成功。
`load_distance_cache()` 校验内容、栅格和来源快照。调用者应传入预期
`config_sha256` 检查当前配置匹配；不传时仅表示归档内部一致。
修改地图、工位、模型或导航配置后必须重建，不能手动改哈希沿用旧矩阵。

## 时间波动与实验口径

截止时间作为从本批出发起算的秒数，逐工位可手动编辑；完成卸货才算交付。
静态距离归档中的 `time_source` 和 `travel_time_sec` 仍为 `null`。
独立实测时间写入另一个 `time_matrix.json`，与距离归档内容哈希绑定，不篡改原距离证据。

Nav2 局部控制使实际时间存在波动。后续算法比较需冻结一份共同的预测矩阵；
独立标定时记录每个有向点对的多次样本、均值和离散程度。正式仿真实验保持地图、
控制参数、速度、停靠朝向、卸货时间和初始化流程一致，重复运行并报告波动。
不得把正式评价运行的实测耗时回填为该次运行的预测时间。

## 独立时间标定

先停止已有仿真，避免两套系统竞争同一 ROS 域或 Gazebo 端口。在已加载环境的终端：

```bash
# 先跑物料站→S1→物料站，共重复五次；只验证测量链路，不生成完整矩阵。
ros2 launch delivery_planner calibration_sim.launch.py \
  distance_file:=/绝对路径/距离归档/matrix.json pilot:=true

# 短路线通过后完整标定：每轮覆盖42条有向边，默认5轮共210段。
ros2 launch delivery_planner calibration_sim.launch.py \
  distance_file:=/绝对路径/距离归档/matrix.json
```

自动入口包含 Gazebo、AMCL 和 Nav2，关闭配送管理器；采样结束或失败时自动关闭该入口。
默认无图形界面，可加 `gui:=true rviz:=true`。`output_dir` 必须是新目录；默认放在 `runs/`。
单次目标超时默认 180 ROS 秒，停车误差要求 ≤0.10 m / 0.10 rad，
成功回调后连续静止至少 0.25 ROS 秒。计时包含导航请求、行驶、最终朝向调整及停车确认；
每段之间默认等待5 ROS秒，等待不计入点间行驶时间。Gazebo暂停不推进这些ROS计时；
另有墙钟看门狗检测进程失联/长时间停滞，触发时标记失败，不伪造时间。

每轮采用固定种子的有向欧拉回路，因此每条边恰好走一次并回到物料站，无需额外转场。
`seed` 仅控制采样顺序，不宣称固定了 AMCL 或物理引擎的随机过程。
各轮更换顺序，不传送车体、不回灌真值定位。每站固定朝向停车，仍可能存在定位历史影响，
这些连续样本不应声称为独立同分布。五次样本只提供初步波动指标，不代表充分统计显著性。

`time_matrix.json` 保存所有成功、失败和未完成记录、每边均值/样本标准差/P95/范围/成功率/样本数，
`trajectory.csv` 保存10 Hz采样的AMCL、轮式里程计和Gazebo world真值，后者只用于评估。
`runtime_parameters.json` 保存实际生效参数；采样前与距离归档中参数、地图及模型核验。
任何导航失败、碰撞包络重叠或超时都会停止采样；失败不会被删除再凑够成功次数。
完整缓存要求所有42边达到规定次数、没有失败、流程正常结束。部分结果仍保留，但不能直接用于优化。

可选参数：`repeats`（默认5、至少2）、`seed`、`hold_sec`、`timeout_sec`。
比较算法时冻结同一份距离与时间缓存；导航配置变化后重新标定，而不是混合不同版本的样本。
统计实验也要统一 GUI/RViz 开关及机器负载条件；演示截图可单独录制并标注为展示运行。

## 手动截止时间与精确枚举

编辑 `config/instance_manual.yaml` 中的 `tasks.S1.due_sec` 等字段即可调整截止时间；
`service_sec` 是对应工位的卸货秒数。两者必须为有限非负数。配置中的现有数值是明确标注的
演示值，不是生产要求，也没有作为论文中的正式截止时间实例。
该配置用于离线评价，尚不改变当前 `delivery_tasks` 固定顺序执行器的统一卸货时长。

```bash
ros2 run delivery_planner evaluate_routes.py \
  --distance /绝对路径/距离归档/matrix.json \
  --time /绝对路径/完整时间归档/time_matrix.json \
  --instance src/delivery_planner/config/instance_manual.yaml \
  --output runs/新的穷举结果目录
```

程序拒绝缺失样本、过期配置绑定或损坏的时间归档。六工位枚举720种排列；
输出每条顺序的到达/交付完成时刻、累计迟交、包含回程的距离和总时长，以及全部非支配顺序。
相同目标值的不同顺序均保留。不可达边导致该顺序不可行；迟到属于软约束，仍可行。
这份精确Pareto集合是后续NSGA-II的核对参照，不是NSGA-II的运行结果。
