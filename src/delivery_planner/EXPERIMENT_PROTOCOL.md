# 冻结优化输入与执行验证协议

本协议落实 2026-10-27 的研究口径。优化目标始终为：包含回程的规划距离，
以及完成卸货后计算的累计迟交；总运行时间是辅助指标，不替代迟交目标。

## T4：代价生成、冻结与验证（修订表述）

在正式算法实验前，固定地图、工位 Pose、Global Planner、footprint、膨胀层及参数，
通过显式 start/goal 的 ComputePathToPose 生成各有向点对的全局路径。
不使用 AMCL 当前位姿、不启用动态障碍层、不让机器人实际行驶。
每个点对重复规划三次，检查距离和原始路径一致性；不一致则保留证据并拒绝该边，
不能用平均值掩盖不一致。当前距离值选用通过检查后的第一条 Path 折线长度。

时间由独立标定运行从导航目标发出到到站停车确认测量，不含卸货时间。
每边正式标定默认五次；保留成功、失败、未完成、超时、原始轨迹及条件快照，
报告成功完成样本的均值、样本标准差、经验 P95、样本数，以及全部已结束尝试的成功率。
冻结通过完整性与质量检查的距离矩阵、时间矩阵和任务实例，赋予共同输入指纹。
所有算法评价同一冻结版本，迭代中不调用 Gazebo，不用正式评价运行回填矩阵。

执行验证在同一场景、机器人、Nav2 参数、速度限制、服务规则、截止时间及初始化流程下，
对预先选定的代表顺序各重复至少五次，报告实际距离、实际累计迟交、时长、成功率和波动。
预测与执行结果分表保存，分析模型误差，不能声称每次实际轨迹或耗时相同。
修改运行条件后生成新实验版本；旧记录和失败均保留，不合并成同一冻结输入。

## 数学定义与统计边界

以物料站为 0，访问顺序为 π，π₀=πₙ₊₁=0：

```text
d_plan(i,j) = Σ ||Path[k+1].xy - Path[k].xy||₂
D_plan(π) = Σ(k=0..n) d_plan(πk, πk+1)
C_hat[0] = 0
C_hat[k] = C_hat[k-1] + t_hat(πk-1, πk) + service[πk]
L_hat(π) = Σ(k=1..n) max(0, C_hat[k] - due[πk])
```

`due_sec`、`service_sec` 可逐工位手动修改，秒为单位，截止时间从本批出发起算。
卸货结束才算交付。回程计入 D_plan 和批次总时长，不再产生工位迟交。
代码保留字段 `distance_m`、`tardiness_sec`，但输出明确标识这是预测模型。

**平均时间代入非线性迟交函数，不等于真实迟交的期望。** 例如完成时刻等概率为0或20秒、
截止10秒：平均时刻的迟交为0，实际期望迟交为5秒。若矩阵均值确实代表对应运行条件的
边时间期望，则由凸性有 Σ max(E[C]-due,0) ≤ E[Σ max(C-due,0)]。
因此当前准确名称为“基于平均运行时间的预测累计迟交”，不声称直接求解随机期望迟交。
若研究目标改为期望迟交/尾部风险，需另行定义情景采样及风险目标，并给所有算法同一组情景。

均值、标准差和分位数在有失败时属于**成功条件下的完成时间统计**，不等于无条件运行时间。
超时只说明在截止观察时刻尚未完成，是右删失信息；不能作为恰好180秒的完成样本，
也不能删除失败后把成功均值冒充总体均值。当前正式冻结策略保守地拒绝有失败、
未完成或次数不足的矩阵；这是一项可用性规则，不代表测得零失败就证明真实成功率为100%。

P95 使用排序后的 `(n-1)*0.95` 位置线性插值（type 7）。五次样本可计算描述性经验P95，
但不足以保证尾部估计精度。用户示例 13.2、13.8、13.4、14.1、13.5 的均值为13.6，
此定义的P95为14.04秒。应结合样本量和波动决定是否追加实验，不宣称五次就是充分统计证据。

当前控制器为 RPP，而不是 DWB。采样顺序种子只固定点对顺序，不能据此声称固定了 AMCL
随机过程或全部动力学随机性。连续停靠样本可能受上一段定位/控制状态影响，固定停靠朝向
与停车条件可以减少影响，但不能证明独立同分布。代表路线验证用于检验这种模型误差。

固定输入也不保证所有种类的规划器都确定性输出；随机规划器还需声明种子与生成协议。
当前使用 Navfn，采取距离容差1e-6米且原始路径点严格相同的校验，不把同长度不同路线混为一致。

## 输入冻结与评价

```bash
ros2 launch delivery_planner cost_matrix.launch.py
# 新距离归档必须先完成三次一致性检查。
ros2 launch delivery_planner calibration_sim.launch.py \
  distance_file:=/绝对路径/距离归档/matrix.json repeats:=5

ros2 run delivery_planner freeze_experiment.py \
  --distance /绝对路径/距离归档/matrix.json \
  --time /绝对路径/时间归档/time_matrix.json \
  --instance src/delivery_planner/config/instance_manual.yaml \
  --output runs/frozen_instance_v1

ros2 run delivery_planner evaluate_routes.py \
  --bundle runs/frozen_instance_v1 --output runs/enumeration_v1
```

冻结目录复制归档、快照及任务配置，不覆盖源文件。`experiment.json` 保存共同输入指纹；
读取时重新核对哈希。修改任务期限也会改变实例身份，应新建实验版本，而非修改已发布目录。
旧命令的三个独立输入参数仍可用于工程检查；正式算法比较建议统一使用 `--bundle`。
六任务枚举720种顺序并生成精确Pareto集合；NSGA-II、MOEA/D尚未实现，不把枚举冒充它们。

## 预测与执行结果分离

| 指标 | 来源 | 用途 |
|---|---|---|
| D_plan | 冻结全局路径距离矩阵 | 优化目标1 |
| L_hat | 冻结平均时间、服务时间、截止时间 | 优化目标2 |
| D_odom | 连续轮式里程计增量 | 执行观测，可能受滑移影响 |
| D_truth | Gazebo真值连续采样 | 仿真执行评估，不用于导航反馈 |
| L_actual | 记录的卸货完成时刻减截止时间 | 执行迟交，不回填预测矩阵 |

算法实验固定实例、矩阵、预算与种子集合；执行实验固定物理/导航条件，交错安排方案顺序。
失败批次报告失败和未完成工位，不按零迟交计入成功批次均值。
目前执行器还未接入逐工位期限和这些完整对比字段；本次完成输入协议与工具，
不能把本节列出的后续验收要求表述为已经做完代表路线五次执行验证。

## 已知实际限制

2026-10-11 的短路线三次往返均成功，但属于试采样；正式全矩阵采集在第12段 S6→S1
达到180秒超时，保留11段成功和1段失败，随后自动停止。
超时段起步50秒只平移约0.42米，里程计角速度多次反向；终点附近的位置误差约0.068米，
朝向误差约0.57 rad。根因未确认。冻结矩阵方法不能使此失败变成成功，也不能证明任意点对执行稳定。
因此当前没有可发布的完整实测时间矩阵，也没有基于完整实测矩阵的论文算法比较结果。
